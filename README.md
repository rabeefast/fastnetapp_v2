# Fast Net — تطبيق إدارة بطاقات الإنترنت

نظام لإدارة بطاقات User Manager (المخزون على disk1 داخل الراوتر RB1100Dx4)
وحركتها بين المدير والوكلاء ونقاط البيع بالأجل، مع مزامنة سحابية وتليجرام.

## الوظائف الموجودة في هذه النسخة

- [x] الدخول بالبريد/كلمة المرور عبر Firebase Auth (أول حساب يدخل = المدير)
- [x] فصل الأدوار: مدير / وكيل / نقطة بيع
- [x] تبويب «الفئات» في إعدادات المدير: عدد الفئات + الأسماء + أسمائها في User Manager
- [x] تسعيرة المسارين (مدير←وكيل / وكيل←نقطة بيع) قابلة للتعديل بالكامل من الإعدادات
- [x] حجم الصفحة وعدد المجاني بعدها مرنان (الحساب المالي هو المرجع)
- [x] حد تنبيه انخفاض المخزون + ربط تليجرام (توكن على جهاز المدير فقط) + رسالة اختبار
- [x] استيراد ملف أو عدة ملفات PDF في دفعة واحدة، مع تعيين فئة مستقلة لكل ملف
- [x] استخراج اسم المستخدم والرقم التسلسلي ورقم الصفحة تلقائيًا مع معاينة وتحقق من التكرار
- [x] عرض جدول لكل دفعة: الفئة، الرقم التسلسلي، اسم المستخدم، الصفحة، وحالة المطابقة مع User Manager
- [x] إنشاء دفعات يدوية عند الحاجة، مع عدم استبدال أسماء مستخدمين موجودة
- [x] قفل التطبيق اختياريًا بالبصمة/المصادقة الحيوية من إعدادات الحساب
- [x] مربعات اختصار أيقونية في الرئيسية تفتح التبويب المختار
- [x] تسليم المخزون من المدير للوكيل ومن الوكيل لنقطة البيع
- [x] حساب المديونية وتسجيل السداد
- [x] سجل تسليمات المدير، وتسجيل بيع الكروت بأرقام منفردة أو نطاقات
- [x] مزامنة حالة User Manager للقراءة فقط عبر RouterOS API
- [x] اختبارات الحساب المالي والتحقق من ترجمة ملفات التطبيق وبناء APK عبر GitHub Actions

## ملاحظات قبل الاستخدام

- استيراد PDF يتطلب ملفًا نصيًا قابلًا للاستخراج؛ الملفات الممسوحة كصور أو المحمية بكلمة مرور تُرفض بدل تخمين أرقام البطاقات.
- يقرأ التطبيق PDF محليًا وقت الاستيراد، ويحفظ بيانات الكروت واسم الملف فقط؛ لا يرفع نسخة PDF الأصلية إلى Firebase.
- تُطابق حالة User Manager مع اسم المستخدم فقط؛ الرقم التسلسلي يبقى رقمًا مطبوعًا مستقلًا في التطبيق.
- يمكن اختيار عدة ملفات دفعة واحدة، وتعيين فئة لكل ملف. يحاول التطبيق استنتاج الفئة من اسم الملف ثم يسمح بتعديلها قبل الحفظ.
- الحد الأقصى للاستيراد في دفعة واحدة 10000 بطاقة، وأسماء المستخدمين المتكررة أو الموجودة مسبقًا لا تُستبدل.
- الاتصال الحي بالراوتر لم يُختبر من بيئة التطوير؛ يلزم اختباره على شبكة الراوتر قبل الاعتماد عليه.
- قواعد Firestore الإنتاجية: يجب إعدادها والتحقق منها قبل استخدام بيانات حقيقية.
- يثبت GitHub Actions Flutter 3.32.0 وAndroid NDK 27.3.13750724 على Ubuntu 24.04 لتفادي أخطاء توافق pdfrx 1.3.5 وتنزيلات NDK المتغيرة.

## خطوات التشغيل (بالترتيب)

### 1) إنشاء Firebase (بحساب Gmail)

1. ادخل `console.firebase.google.com` وسجّل بحساب Gmail
2. Create project → اسم مثل `fastnet-cards`
3. Authentication → Get started → فعّل **Email/Password**
4. Project settings → Your apps → أيقونة Android:

- Package name: `com.fastnet.fastnet_app`
- اترك SHA-1 فارغًا واضغط Register

5. يتضمن `lib/firebase_options.dart` إعداد مشروع `fast-net2` الموجود في النسخة
المرفقة. إذا استخدمت مشروع Firebase مختلفًا، أعد توليد الإعدادات لتطبيق Android
باسم الحزمة `com.fastnet.fastnet_app` بدل استبدال القيم عشوائيًا.
6. Firestore Database → Create database → **Production mode** → أقرب region

### 2) أمان Firestore

لا تستخدم قاعدة عامة من نوع `allow read, write: if request.auth != null`؛ فهي تسمح
لكل مستخدم مسجل بقراءة وتعديل بيانات جميع الحسابات والمخزون والمديونيات. يلزم نشر
قواعد تقصر الوصول حسب الدور والملكية قبل تشغيل التطبيق على بيانات حقيقية. لم أضع
قواعد غير مختبرة قد تمنح صلاحيات أوسع أو تمنع التطبيق من العمل.

### 3) إنشاء حسابات الوكلاء ونقاط البيع

من Firebase Console → Authentication → Users → Add user
ثم من Firestore → collection `users` → أضف مستندًا بمعرف الـ UID الخاص بالمستخدم:

```javascript
{ name: "اسم الوكيل", role: "agent", phone: "777...", parentUid: "UID_المدير" }
```

ولنقطة البيع: `role: "pos"` و `parentUid: "UID_الوكيل"`

### 4) بناء APK عبر GitHub (بدون تثبيت أي شيء على جهازك)

1. أنشئ حساب GitHub مجاني، ثم New repository باسم `fastnet_app` (خاص Private)
2. ارفع محتويات هذا المجلد (من تبويب Add file → Upload files، أو بأوامر git)
3. من تبويب **Actions** ستبدأ عملية البناء تلقائيًا خلال دقائق
4. عند الانتهاء: قسم **Artifacts** → حمّل `FastNet-APK` → الملف `app-release.apk`
5. انقله لجوالك وثبّته (اسمح بالتثبيت من مصادر غير معروفة)

### 5) حساب API للراوتر (اختياري)

أنشئ مستخدمًا مستقلًا للقراءة فقط، بسياسة `read,api` دون `write` أو `policy`.
إذا لم تكن مجموعة `fastnet-read` موجودة، أنشئها أولًا من Winbox أو Terminal، ثم أضف المستخدم:

```javascript
/user group add name=fastnet-read policy=read,api
/user add name=fastnetapi group=fastnet-read password=كلمة_قوية_جدا comment="FastNet App read-only"
```

- إذا كانت المجموعة موجودة، لا تنشئها مرة أخرى؛ تحقق من أن صلاحياتها `read,api` فقط.
- فعّل خدمة API على المنفذ 8728، واسمح بها من شبكة LAN موثوقة فقط أو عبر VPN.
- **لا تفتح المنفذ 8728 على الإنترنت.** اتصال RouterOS API هنا غير مشفّر، وكلمة المرور تحفظ محليًا في تفضيلات التطبيق غير المشفّرة. استخدم كلمة مرور مخصصة وقوية.
- شاشة الراوتر متاحة للمدير. الاتصال يقرأ أسماء مستخدمي User Manager ويطابقها مع معرّفات مستندات الكروت في Firestore.
- المزامنة تكتب `um_used` و`um_profile` في Firestore؛ لذلك يجب أن تسمح قواعد Firestore للمدير بتحديث هذه الحقول. لم أضع قواعد مفتوحة أو غير مختبرة.

## بنية البيانات (Firestore)

| المجموعة | الوثيقة | الحقول |
| --- | --- | --- |
| users | uid | name, role(manager/agent/pos), phone, parentUid |
| settings | uid المدير | categories[], lowStockThreshold |
| batches | تلقائي | managerUid, name, categoryKeys, fileNames, pageCount, count, importStatus |
| cards | username | batchId, categoryKey, serial, pageNumber, sourcePdf, status, holderUid, um_found, um_used |
| deliveries | تلقائي | managerUid (للتسليمات الجديدة), fromUid, toUid, batchId, side(mg/ag), items[], totalAmount |
| payments | تلقائي | fromUid, toUid, amount, note |

## مبدأ العمل دون اتصال

مكتبة Firestore تحتفظ بذاكرة محلية على الجوال: يكتب المستخدم بياناته بلا إنترنت،
وتُدفع التغييرات تلقائيًا فور عودة الاتصال — دون أي زر "مزامنة".

## اختبار سريع

1. سجّل دخولك بأول حساب ← يصبح مديرًا تلقائيًا
2. الإعدادات ← تحقق من الفئات والأسعار ← احفظ
3. أدخل توكن البوت و Chat ID ← أرسل رسالة اختبار
4. من الدفعات اختر ملفات PDF، عيّن الفئة لكل ملف، راجع المعاينة ثم احفظ
5. اختبر قفل البصمة من الإعدادات؛ عند عدم توفرها يبقى الدخول بالبريد وكلمة المرور
6. أنشئ حساب وكيل من Console وجرّب دخوله من جوال آخر
